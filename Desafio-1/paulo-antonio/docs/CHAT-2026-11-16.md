## Implementado

- AgentCore Runtime HTTP com ZIP Node.js 22, modelo Haiku 4.5 via ConverseStream.
- Lambda de chat com streaming NDJSON, identidade apenas das claims Cognito e invocação IAM do runtime.
- Histórico completo de mensagens e ferramentas em DynamoDB, por usuário/conversa.
- Endpoints protegidos `POST /chat` e `GET /conversas`.
- Interface local com mensagens incrementais, seleção de conversas e confirmação de compra por botão.
- Consulta de intenção sem pagamento, inclusive para recuperar resultado incerto.
- Permissões separadas entre chat, histórico, runtime e ferramentas.

## Evidências e limites

- Nove testes locais de chat/agente: autenticação, isolamento, confirmação, preservação
  de histórico, limite de rodadas e ausência de repetição automática de pagamento.
- Dez testes de infraestrutura/sessão; build estático e TypeScript passaram.
- Teste visual em Edge headless com API simulada: botão de confirmação, histórico e tela
  de 390 px sem rolagem horizontal. Nenhuma senha/token real usado nesse teste.
- Oito rotas reais rejeitam token ausente e inválido com 401, com CORS para a origem local.
- O teste administrativo da Lambda recebeu streaming até o status do AgentCore.
  A conversa com o Haiku falhou antes de preparar qualquer compra.
- O teste `--expect-unavailable` passou na AWS: mensagem de indisponibilidade correta,
  histórico persistido e recuperado, outro titular recebe 404, lease de execução liberado.
  Esse resultado valida o tratamento de erro, não a conversa com o modelo.
- Fixtures de usuário/conversa criadas durante os testes foram removidas por chaves exatas.
  O limite do usuário real não foi alterado pelos testes automatizados.
